# PBI-00007: Read the files .breadcrumbs names

## Directive

When `bcr extract` is given no operand, read every file `.breadcrumbs`
names, as ADR-0014 and `specs/extract/spec.md` describe. Add this
repository's `.breadcrumbs`.

**Scope:**
- Add a package of its own for the file set, such as
  `internal/fileset`. It is infrastructure (ADR-0013); `internal/crumb`
  does not use it.
- Read `.breadcrumbs` at the root:
  - one pattern per line; blank lines and lines that start with `#`
    are ignored;
  - a pattern is matched against the whole path from the root, with
    `/`: `*` matches any characters but `/`, `?` one character but
    `/`, and `[...]` one character from a set;
  - `!` excludes; the last line that matches a file decides;
  - `**`, a `/` at the end, a leading `/`, or a pattern `path.Match`
    rejects is a problem at its line in `.breadcrumbs`, and then no
    file is read. A leading `/` is not in ADR-0014: add the rule to
    the spec.
- Find the files from the current directory: do not enter `.git/`,
  and do not follow symbolic links, to files or to directories. Read
  them in order of path compared as bytes.
- With no operand and no `.breadcrumbs`, write `bcr: ` and a message
  to standard error, and exit 2. With operands, read exactly those
  files, as before.
- Change the usage line to `usage: bcr extract [FILE...]`.
- Add `.breadcrumbs` at the root of this repository:

  ```
  docs/adrs/*.md
  specs/*/spec.md
  tasks/*.md
  ```

- Add a test for each Scenario of `specs/extract/spec.md` about
  `.breadcrumbs` and the walk, in a temporary directory.
- Describe the no-operand mode and `.breadcrumbs` in `### extract` of
  `docs/bcr.md`. Generate `docs/bcr.1` again.
- Add the new package and `.breadcrumbs` to the Context Map of
  `AGENTS.md`.
