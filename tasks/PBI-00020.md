# PBI-00020: Add bcr report

## Directive

Add the command `bcr report`, as `specs/report/spec.md` describes: it
reads the records of the pipe from standard input and writes one
Markdown page, with every breadcrumb, problem and claim, and one
Mermaid diagram for each spec. It is the last stage of the pipe.

**Scope:**
- Add `internal/page`, which writes the page of a set: the four
  sections, each view as a `flowchart`, and the escaping of every value
  read from a record. It is the only package that knows Markdown and
  Mermaid, and takes what is in a view from the core.
- In `cmd/bcr`, read the whole input before writing anything. When a
  line is not a record, write nothing to standard output and exit 2.
  Print only the page, and exit 0 whatever the verdicts.
- Add a test for each Scenario of `specs/report/spec.md`, a test that
  compares the whole page with a file, and tick its Definition of
  Done.
- Render every diagram of this repository's page with a Mermaid
  viewer, and fix what it refuses.
- Document the command in `docs/bcr.md` under `### report`, and
  generate `docs/bcr.1` again. Add the claim on that heading to the
  spec's breadcrumb.
- Add the four-stage pipe to `AGENTS.md`'s Toolchain, and
  `internal/page` to its Context Map.
- Leave `bcr audit-report` and `internal/report` as they are: they
  belong to the old model.
- Leave `.github/workflows/` as it is: whether CI writes the page is
  not decided.
- Leave `ARCHITECTURE.md` as it is: its update for the pipeline is its
  own change.

## Verification
- [ ] `go test ./...` passes, with a test for each Scenario of
      `specs/report/spec.md`.
- [ ] In this repository,
      `set -o pipefail; bcr extract | bcr verify | bcr audit | bcr report`
      exits 0, lists every breadcrumb and draws one view for each spec.
- [ ] Run twice, it prints the same bytes.
- [ ] With `### verify` changed to `#### verify` in `docs/bcr.md`, on a
      throwaway copy, the page shows the claim and the `verify`
      breadcrumb as `Refuted`.
- [ ] Every diagram of this repository's page is drawn by a Mermaid
      viewer.
- [ ] `go.mod` requires no new module.
- [ ] `go test ./internal/manpage` passes.

## Refinement Protocol
If the page needs a rule the spec does not state, add the rule to the
spec in the same commit. If it needs a change to a record, to what is
in a view, or to the exit status the spec defines, stop and ask.
