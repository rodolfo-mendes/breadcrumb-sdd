# PBI-00025: Add bcr filter

## Directive

Add `bcr filter`, which reads the records of the pipe and prints those
that match its flags, unchanged, as `specs/filter/spec.md` describes:
`--id`, `--type` and `--kind`, each given any number of times. The
spec is on the main branch with no code, and its claim on
`docs/bcr.md` is Refuted until the command is documented.

**Scope:**
- In `cmd/bcr`, add the command `filter` and its usage line, with its
  flags `-i ID`, `--id ID`, `-t TYPE`, `--type TYPE`, `-k KIND` and
  `--kind KIND` (ADR-0006). A record is printed when it matches every
  flag given, and matches a flag when it equals one of its values.
- In `internal/cli`, keep every value of a flag given more than once,
  for the commands that ask for them. `bcr init` still reads the last
  value of `-a`.
- In `internal/records`, add a reader that returns each record with
  its kind, its `ID` and `TYPE` when it has them, and the line as it
  was read, records of a kind `bcr` does not know included (ADR-0011).
- Check only the shape of a record of a kind the pipe prints: its
  number of fields, none of them empty, and its `LINE`. Check no claim
  and no `VERDICT`. State this rule in the spec's Interface.
- Read the whole input before writing, and print each record that
  matches byte for byte, with its line ending, in the order read.
- Add a test for each Scenario of `specs/filter/spec.md`, and tick its
  Definition of Done.
- Document `bcr filter` under `### filter` in `docs/bcr.md`, with its
  flags and its exit status; name it in SYNOPSIS, DESCRIPTION and EXIT
  STATUS; and generate `docs/bcr.1` again (ADR-0008, ADR-0009).
- In AGENTS.md's Toolchain, show how to look up a breadcrumb. In
  ARCHITECTURE.md, name `filter` in the Queries family, and take it
  out of What comes next. In README.md, show `bcr filter` where a
  stage's output is read.
- Put no rule of `bcr filter` in `internal/crumb`: it judges nothing.
