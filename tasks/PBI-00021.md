# PBI-00021: Remove the old model

## Directive

Carry out ADR-0024: delete `breadcrumbs/`, the commands that read it,
the method specification and the site, so that the repository and
`bcr` describe one model, the pipe
`bcr extract | bcr verify | bcr audit | bcr report`.

**Scope:**
- Delete `breadcrumbs/`.
- Remove the commands `check`, `verdict`, `links`, `new`, `spec`,
  `init` and `audit-report` from `cmd/bcr`, with their tests, and
  delete `cmd/bcr/init.go`. Keep the dispatch to `extract`, `verify`,
  `audit` and `report`, and their tests. A removed command is an
  unknown command: `bcr` exits 2 and prints its usage.
- Delete `internal/breadcrumb` and `internal/report`, and remove
  `cli.IDs` and its test from `internal/cli`: only the old commands
  use them.
- Delete `docs/breadcrumb-sdd.md` and `docs/docs.go`.
- Delete `cmd/specsite`, `internal/specsite` and
  `.github/workflows/pages.yml`.
- In `docs/bcr.md`, remove the old commands from SYNOPSIS and
  COMMANDS, describe `bcr` in DESCRIPTION as the four commands of the
  pipe, and cite ADR-0006 as plain text for the command-line
  conventions and the exit status. Write no link to an ADR: the file
  ships in the release, where it would not resolve (ADR-0008).
  Generate `docs/bcr.1` again.
- A comment that cites an old id cites its ADR: ADR-0006 in `cmd/bcr`
  and `internal/cli`, ADR-0008 and ADR-0009 in `internal/manpage`.
  The sample Markdown of `internal/manpage`'s test uses `report` and a
  link to ADR-0006 in place of `audit-report` and an old breadcrumb.
- In `.github/workflows/release.yml`, remove the lines that copy
  `docs/breadcrumb-sdd.md` and the old ids in its comments, naming no
  replacement: the workflow is its own rule (ADR-0024).
- In AGENTS.md, remove the Toolchain rows of the old commands, the
  ASK rules about the method specification and `breadcrumbs/`, the
  ALWAYS rule about `docs/breadcrumb-sdd.md`, and the Context Map
  lines for `docs/breadcrumb-sdd.md`, `internal/breadcrumb` and
  `breadcrumbs/`.
- In the specs, remove the sentences saying an old command stays as
  it is, or is replaced, in `specs/extract`, `specs/verify`,
  `specs/audit` and `specs/report`; the Definition of Done items
  about the old commands in `specs/verify`, `specs/audit` and
  `specs/report`; and the `breadcrumbs/` item of `specs/asdlc`'s
  layout. `specs/asdlc`'s introduction no longer names
  `docs/breadcrumb-sdd.md`. Change nothing else in the specs.
- In `.gitignore`, remove `/audit-report.html` and `/_site/`, which
  only the old report and the site wrote.
- Set ADR-0024's Status to `Accepted`, which the user decided; it
  read `Accept`.
- Leave README.md, CONTRIBUTING.md and ARCHITECTURE.md as they are:
  PBI-00022 rewrites them.
- Do not edit any other ADR, or any other PBI: their mentions of
  `breadcrumbs/` and old ids are history (ADR-0024).
- Do not change `go.mod`: `internal/frontmatter` still uses go-yaml.
- Do not write a new `bcr init`: it returns with its own spec.

## Refinement Protocol
- If a spec sentence about the old model also states a rule of the new
  one, stop and ask before removing it.
- If removing a command breaks code that a new command uses, other
  than `cli.IDs`, stop and ask.
- If the grep check finds a file this PBI does not name, report it
  rather than editing it.
