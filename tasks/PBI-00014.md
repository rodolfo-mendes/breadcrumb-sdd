# PBI-00014: Print problems as records in bcr extract

## Directive

Make `bcr extract` print each problem it finds as a `problem` record
on standard output, as well as on standard error, as
`specs/extract/spec.md` describes, so the stages after it in the pipe
can see it (ADR-0021).

**Scope:**
- In `internal/records`, write a `problem` record: `PATH`, `LINE` and
  `MESSAGE`, with a space in place of a tab or a line ending in the
  message. `records.Read` keeps skipping the kinds it does not know,
  so `bcr verify` does not change.
- In `cmd/bcr`, print a file's `problem` records after its other
  records, in order of line, and the problems of `.breadcrumbs` as
  records whose `PATH` is `.breadcrumbs`.
- Print no record for a message that starts `bcr: `.
- Leave standard error and the exit status as they are.
- Add a test for each Scenario of `specs/extract/spec.md` that has
  none, and tick its Definition of Done.
- Document the `problem` record in `docs/bcr.md` under `### extract`,
  and generate `docs/bcr.1` again.
- Do not print the problems of `bcr verify` as records: that is
  PBI-00015.

## Dependencies
- Blocked by: None
- Must merge before: PBI-00015

## Context
Read: `specs/extract/spec.md`
- Interface, for the `problem` record and where it comes in the output

## Verification
- [ ] `go test ./...` passes, with a test for each Scenario of
      `specs/extract/spec.md`.
- [ ] In this repository, `bcr extract | grep -c '^problem'` prints 0.
- [ ] In this repository, `set -o pipefail; bcr extract | bcr verify > /dev/null`
      prints nothing and exits 0.
- [ ] `go.mod` requires no new module.
- [ ] `go test ./internal/manpage` passes.

## Refinement Protocol
If printing a problem as a record needs a rule the spec does not
state, add the rule to the spec in the same commit. If it needs a
change to the fields of the record, to standard error, or to the exit
status the spec defines, stop and ask.
