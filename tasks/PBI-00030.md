# PBI-00030: Read types, verbs, subjects and claims for bcr verify

## Directive

Give `bcr verify`'s record reader what the checks against
`breadcrumb.rules` need (ADR-0025): the type of a breadcrumb, the
verb of a link and the id of the breadcrumb it is written in, and
each `claim` record, for the id of its breadcrumb and its place.
`bcr verify` checks no shape yet: the command follows in PBI-00031.

**Scope:**
- In `internal/records`, `Read` fills the type of a breadcrumb, and
  the verb and the subject's id of a link.
- `Read` reads a `claim` record for its `ID`, `PATH` and `LINE`. Its
  kind, target and argument are not checked: they stay `bcr audit`'s
  (ADR-0019).
- A `claim` record with fewer than seven fields, an empty field among
  them or a `LINE` that is no line number is no longer skipped: it
  stops `bcr verify` with exit status 2, as it stops `bcr audit`.
- `ReadReport` fills the subject's id of a link too.
- A test for the Scenarios "Records of a kind it does not know",
  which now uses a `note` record, and "A claim record that is not a
  record".

## Dependencies
- Blocked by: PBI-00028
- Must merge before: PBI-00031

## Context
Read: `specs/verify/spec.md`, the records `bcr verify` reads.

Read: ADR-0011, for the records; ADR-0016, for the copy.

## Verification
- [ ] `go vet ./...` and `go test ./...` pass.
- [ ] `set -o pipefail; go run ./cmd/bcr extract | go run ./cmd/bcr verify | go run ./cmd/bcr audit > /dev/null`
      prints nothing and exits 0.
- [ ] `go run ./cmd/bcr extract > a.tsv; go run ./cmd/bcr verify < a.tsv | cmp - a.tsv`
      exits 0.

## Refinement Protocol
If reading a record needs a rule the spec does not state, add the
rule to the spec in the same commit. If a record `bcr extract` prints
today would stop `bcr verify`, stop and ask.
