# PBI-00039: Show a report's diagram on the landing page

## Directive

Add the section "The report" to the landing page: what `bcr report`
shows, a static picture of one of its diagrams to illustrate it, and a
link to its documentation. No link to a live report.

**Scope:**
- In `site/content/_index.md`, the section `## The report {#report}`
  after "How it works", with its picture, caption, and a link to
  `docs/#report`.
- In `site/hugo.toml`, its menu entry, between "How it works" and
  "Honest scope".
- In `site/assets/style.css`, a light card for a picture, and the
  style of its caption.
- `site/static/report-filter.png`: a screenshot of a diagram from a
  real report, as GitHub draws it in a Check run's summary. The draft
  names the `filter` diagram of the run on de667d8, the morning its
  claim was Refuted; another real diagram will do, if its alt text and
  caption say what it shows and where it comes from.
- In `.github/workflows/pages.yml`, the picture checks of the spec,
  in the spec's order.
- In `specs/site/spec.md`: the claim on the new heading, the seventh
  section, pictures in the Architecture and under Constraints, the
  picture guardrail, and its Scenario.
- In `docs/bcr.md`, `### report`, and in `README.md`: GitHub does not
  draw the diagrams "wherever it shows Markdown"; release notes show
  them as code, as checked in a draft release on 2026-10-10. Say where
  it draws them, and generate `docs/bcr.1` again
  (`go test ./internal/manpage -update`).

## Dependencies
- Blocked by: None
- Must merge before: None

## Context
Read: `specs/site/spec.md`.

Read: `docs/bcr.md`, `### report`, which the section's text follows.

## Verification
- [ ] `set -o pipefail; go run ./cmd/bcr extract | go run ./cmd/bcr verify | go run ./cmd/bcr audit > /dev/null`
      prints nothing and exits 0.
- [ ] With the pinned Hugo, the build and each Regression Guardrail
      of the spec pass on `PUBLIC`; the link to `docs/#report` reaches
      its heading.
- [ ] Without `site/static/report-filter.png`, the picture check
      prints `report-filter.png`.
- [ ] In both colour schemes, the picture sits on a light card and its
      outlines are visible; at 375px it fits the width.
- [ ] The alt text and the caption describe the picture used.
- [ ] `grep -rn 'wherever it shows Markdown' docs README.md` prints
      nothing, and `go test ./internal/manpage` passes.

## Refinement Protocol
If the picture cannot be made from real `bcr report` output, stop and
ask: the spec does not allow a picture drawn by hand.
