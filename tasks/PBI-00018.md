# PBI-00018: Add bcr audit

## Directive

Add the command `bcr audit`, as `specs/audit/spec.md` describes: it
reads records from standard input, checks each claim against its
target in the working tree, copies its input, and adds the verdict of
each claim and of each breadcrumb (ADR-0023). Run it in the pipe, in
CI and in `AGENTS.md`.

**Scope:**
- In `cmd/bcr`, read the whole input and every target before writing
  anything. When a line is not a record, or a target cannot be read,
  write nothing to standard output and exit 2.
- Copy the input byte for byte, then write one `claim-verdict` record
  for each claim and one `verdict` record for each breadcrumb, with
  the records package.
- Print each Refuted claim to standard error as `PATH:LINE: MESSAGE`,
  and exit 1 when there is one. Undecided does not fail.
- Add a test for each Scenario of `specs/audit/spec.md`, and tick its
  Definition of Done.
- Document the command in `docs/bcr.md` under `### audit`, and
  generate `docs/bcr.1` again. Add the claim on that heading to the
  spec's breadcrumb.
- Add `bcr audit` to the pipe in `.github/workflows/check.yml` and in
  `AGENTS.md`'s Toolchain, with standard output sent to `/dev/null`,
  so the log shows problems and Refuted claims, not every record.
- In `specs/asdlc/spec.md`, name the three-stage pipe in the
  Definition of Done, and say that `bcr audit` checks the claims.
- Leave `bcr check`, `bcr verdict` and `bcr audit-report` as they are:
  they belong to the old model.
- Leave `ARCHITECTURE.md` as it is: its update for the pipeline is its
  own change.

## Refinement Protocol
If the command needs a rule the spec does not state, add the rule to
the spec in the same commit. If it needs a change to a record, to how
a verdict is built, or to the exit status the spec defines, stop and
ask.
