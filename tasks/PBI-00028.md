# PBI-00028: Hold a repository's rules in the core

## Directive

Give the core the shape a repository declares in `breadcrumb.rules`
(ADR-0025), and the checks against it. No file is read here, and
`bcr verify` does not change yet: the reader, the records and the
command follow in PBI-00029, PBI-00030 and PBI-00031.

**Scope:**
- In `internal/crumb`, add `Rules`: the types, the link rules and the
  types that may carry claims, each with its line, and the name a
  message calls them by.
- `Rules.Check` returns the problems of the rules as a whole: a rule
  written twice, and a `link` or `claims` rule that names a type no
  rule declares.
- `Set.CheckShape` returns each breadcrumb, link and claim of a set
  that breaks the rules, with the messages `specs/verify/spec.md`
  gives, and judges neither a link nor a claim whose cause is already
  a problem.
- A link of a set gains the id of the breadcrumb it is written in.
- `SortProblems` puts problems in order of place, so the command can
  merge the problems of both checks.
- Tests build their rules and sets as values.

## Dependencies
- Blocked by: None
- Must merge before: PBI-00029, PBI-00030, PBI-00031

## Context
Read: `specs/verify/spec.md`, the rules about `breadcrumb.rules`.

Read: ADR-0025, for the shape; ADR-0013, for what belongs to the core.

## Verification
- [ ] `go vet ./...` and `go test ./...` pass.
- [ ] `go list -f '{{.Imports}}' ./internal/crumb` lists only the
      standard library.
- [ ] `set -o pipefail; go run ./cmd/bcr extract | go run ./cmd/bcr verify | go run ./cmd/bcr audit > /dev/null`
      prints nothing and exits 0.

## Refinement Protocol
If a check needs a rule the spec does not state, add the rule to the
spec in the same commit. If it needs a decision ADR-0025 does not
take, stop and ask.
