# PBI-00031: Check a repository's shape in bcr verify

## Directive

Make `bcr verify` read `breadcrumb.rules` from the current directory
and check the set against the shape it declares (ADR-0025): the type
of each breadcrumb, the links allowed between types, and the types
that may carry claims. With no such file, `bcr verify` does what it
did before.

**Scope:**
- In `cmd/bcr`, `bcr verify` reads `breadcrumb.rules` through
  `internal/rules`. A missing file means no shape; a file that cannot
  be read is exit status 2, with nothing copied.
- A problem in the file is printed at `breadcrumb.rules:LINE`, and as
  a `problem` record. No shape check then runs; the checks about ids
  and links still do.
- With a valid file, the problems of `Set.CheckShape` join those of
  `Set.Check`, in order of place.
- A test for each Scenario of `specs/verify/spec.md` about
  `breadcrumb.rules`; tick its Definition of Done.
- Describe `breadcrumb.rules` and the checks under `### verify` in
  `docs/bcr.md`, and generate `docs/bcr.1` again (ADR-0008,
  ADR-0009).
- Name `internal/rules` in ARCHITECTURE.md and in AGENTS.md's Context
  Map.

This repository gets its own `breadcrumb.rules` in PBI-00032.

## Refinement Protocol
If a check needs a rule the spec does not state, add the rule to the
spec in the same commit. If it needs a decision ADR-0025 does not
take, or changes what `bcr verify` prints with no `breadcrumb.rules`,
stop and ask.
