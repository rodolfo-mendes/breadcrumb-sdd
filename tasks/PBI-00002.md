# PBI-00002: Read a breadcrumb in the core

## Directive

Add the core package that turns a breadcrumb's properties into a
breadcrumb and its links, or into the problems that stop it, as
`specs/extract/spec.md` describes. It knows no file format
(ADR-0013): it gets each property's value as the text written, or a
list of such texts, with its line, from whatever reads the file.

**Scope:**
- Add the package `internal/crumb`. It holds the breadcrumb, the link,
  the problem, and the properties the core is given.
- Check what ADR-0013 gives the core:
  - `id`, `type` and `links` are present; a missing one is a problem
    at the line of the breadcrumb.
  - `id` and `type` are text, not empty, with no white space.
  - `links` is a list; with no value, or with text, it is a problem
    at its line.
  - Each link entry is two words, is not written twice, and does not
    point to its own breadcrumb (ADR-0012); each problem is at the
    entry's line.
- Return every problem of a breadcrumb, in order of line; a
  breadcrumb with a problem returns no breadcrumb.
- Ignore properties other than `id`, `type` and `links`.
- Test the package with breadcrumbs built as values; no test reads a
  file or YAML text.
- Change `specs/extract/spec.md` as ADR-0013 says: the front matter
  reader checks ADR-0002's part of YAML, and the core checks the
  breadcrumb's properties and links. Add Scenarios for the rules above
  that it has none for.
- Add `internal/crumb` to the Context Map of `AGENTS.md`.
- Leave `cmd/`, `internal/breadcrumb`, `go.mod` and `docs/bcr.md` as
  they are.

## Refinement Protocol

spec in the same commit. If a rule seems to belong to the format, not
the core, stop and ask: ADR-0013 draws that line.
