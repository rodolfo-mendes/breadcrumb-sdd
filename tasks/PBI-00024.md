# PBI-00024: Add bcr init for the new model

## Directive

Add `bcr init`, which sets a repository up for the pipe, as
`specs/init/spec.md` describes: `.breadcrumbs` with comments only, a
`## Breadcrumbs` section in the agents file, and a GitHub Actions
workflow that runs the pipe with the release of `bcr` that wrote it.
ADR-0024 removed the old `bcr init`, and decided it is written again
for the new model before the next release.

**Scope:**
- Write `specs/init/spec.md`, whole, with this PBI.
- In `cmd/bcr`, add the command `init` and its usage line, with its
  flag `-a FILE`, `--agents-file FILE`, read by `internal/cli`
  (ADR-0006). Read the release version from `main.version`, which the
  release workflow already sets, or from the version Go records for a
  build such as `go install …@v0.8.0`.
- Find every piece to write before writing the first, write only what
  is missing, replace no file, and add to the agents file only at its
  end.
- Hold the text of each piece in `bcr`. The workflow's actions are
  pinned to the commits `check.yml` uses.
- Add a test for each Scenario of `specs/init/spec.md`, and tick its
  Definition of Done.
- Document `bcr init` under `### init` in `docs/bcr.md`, with its flag
  and its exit status; name it in SYNOPSIS and DESCRIPTION; and
  generate `docs/bcr.1` again (ADR-0008, ADR-0009). The conventions no
  longer say no command takes a flag.
- In README.md, set a repository up with `bcr init` before listing its
  patterns. In ARCHITECTURE.md, add the Setup family, and take
  `bcr init` out of What comes next.
- Put no rule of `bcr init` in `internal/crumb`: it reads no
  breadcrumb.
- Do not run `bcr init` in this repository: its own CI is `check.yml`.

## Dependencies
- Blocked by: PBI-00021
- Must merge before: None

## Verification
- [ ] `go vet ./...` and `go test ./...` pass, with a test for each
      Scenario of `specs/init/spec.md`.
- [ ] `set -o pipefail; go run ./cmd/bcr extract | go run ./cmd/bcr verify | go run ./cmd/bcr audit > /dev/null`
      prints nothing and exits 0.
- [ ] In a new directory, a `bcr` built with
      `-ldflags "-X main.version=0.8.0"` runs `bcr init`, then the
      pipe, which exits 0 with a page that says `No breadcrumbs.`.
- [ ] `go run ./cmd/bcr init` exits 2 and writes nothing.
- [ ] `go test ./internal/manpage` passes.

## Refinement Protocol
If setting up a piece needs a rule the spec does not state, add the
rule to the spec in the same commit. If it needs a change to what
`bcr init` writes, to what it replaces, or to its exit status, stop
and ask.
