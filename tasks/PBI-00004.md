# PBI-00004: Add bcr extract

## Directive

Add the command `bcr extract FILE...`, as `specs/extract/spec.md`
describes: for each file, it reads the breadcrumb with
`internal/frontmatter`, checks it with `internal/crumb`, and prints
its records, or its problems.

**Scope:**
- Add `extract` to `cmd/bcr`, with the usage line
  `usage: bcr extract FILE...`. It takes no flags; flags and `--`
  are read with `internal/cli`, as for the other commands (ADR-0006).
- For each operand, in the order given:
  - read the file; when it cannot be read, write `bcr: ` and the
    error to standard error, and go on with the next;
  - print the problems of the format, or else of the core, as
    `PATH:LINE: MESSAGE`, in order of line, to standard error;
  - with no problem, print the `breadcrumb` record and then a `link`
    record for each link, tab-separated, to standard output.
- `PATH` is the operand as given. Which files to read, and how they
  are named, is the caller's choice: `bcr extract` checks neither the
  name nor the path of a file. A file of any kind whose first line is
  not `---` has no front matter, and prints nothing.
- Exit 2 when there is no operand or a file cannot be read; else 1
  when a file has a problem; else 0.
- Add a test for each Scenario of `specs/extract/spec.md` that has
  none, running `bcr extract` on files in a temporary directory.
- Document `bcr extract` in `docs/bcr.md`: a line in SYNOPSIS and a
  `### extract` subsection under COMMANDS, laid out as ADR-0008 says,
  with no link to the spec. Generate `docs/bcr.1` again
  (`go test ./internal/manpage -update`).
- Add to `specs/extract/spec.md` the rules above it does not state.
- Leave `bcr list`, `internal/crumb` and `internal/frontmatter` as
  they are.
