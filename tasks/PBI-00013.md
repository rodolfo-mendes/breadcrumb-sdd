# PBI-00013: Move the specs' claims into their front matter

## Directive

Move the five claims written in the bodies of `specs/asdlc/spec.md`,
`specs/extract/spec.md` and `specs/verify/spec.md` into the `claims`
of each spec's breadcrumb, as `has-line` claims (ADR-0017, ADR-0019),
and say so in `specs/asdlc/spec.md`.

**Scope:**
- Write these claims, each in the front matter of the spec that holds
  it today:

  | Spec | Claim |
  |---|---|
  | `specs/asdlc/spec.md` | `'AGENTS.md has-line This repository is developed with ASDLC'` |
  | `specs/asdlc/spec.md` | `'docs/adrs/ADR-0001-adopt-asdlc.md has-line Status: Accepted'` |
  | `specs/extract/spec.md` | `'docs/bcr.md has-line ### extract'` |
  | `specs/verify/spec.md` | `'docs/bcr.md has-line ### verify'` |
  | `specs/verify/spec.md` | `'docs/bcr.md has-line Output: standard input, copied to standard output byte for byte.'` |

- Remove the `Claims:` lists from the specs' bodies. Each Regression
  Guardrail keeps its sentence, so a reader still sees what it guards.
- In `specs/asdlc/spec.md`, rewrite the Claims item of its Constraints:
  claims are written in the breadcrumb's front matter (ADR-0017),
  their only kind is `has-line` (ADR-0019), and until `bcr audit`
  checks them they are checked by hand, with the command ADR-0019
  gives.
- Change no other text of the specs.

## Refinement Protocol
If a claim does not hold once moved, stop and ask: the claim is not
edited to turn it true (AGENTS.md).
