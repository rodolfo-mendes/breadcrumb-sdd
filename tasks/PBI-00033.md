# PBI-00033: Set up the ASDLC layout with bcr init --layout asdlc

## Directive

Add `--layout` to `bcr init`, with one layout, `asdlc`, as ADR-0027
decides: besides the pieces `bcr init` always sets up, it writes the
layout's `breadcrumb.rules`, a `.breadcrumbs` that names ASDLC's files
and excludes two templates, the three templates, and a `## ASDLC`
section in the agents file. The first line of each `.breadcrumbs` and
`breadcrumb.rules` `bcr init` writes names the command and the
release, with or without a layout.

**Scope:**
- In `cmd/bcr`, add the flag `-l LAYOUT`, `--layout LAYOUT` to
  `bcr init` and its usage line (ADR-0006). A layout `bcr` does not
  know is a usage error that names the layouts it knows.
- With `--layout`, write nothing and exit 2 when `.breadcrumbs` or
  `breadcrumb.rules` is there, with a message that says to delete both
  to set the layout up again.
- Write `breadcrumb.rules` and `.breadcrumbs` exactly as ADR-0027
  shows them, after their first line.
- Write `docs/adrs/TEMPLATE.md`, `specs/TEMPLATE.md` and
  `tasks/TEMPLATE.md` with ASDLC's sections. Each starts with a valid
  breadcrumb of its type, `links: []`, and the links the layout allows
  as comments; the spec template also has `claims: []`.
- Add the `## ASDLC` section to the agents file, beside
  `## Breadcrumbs`, each found by its heading. It points to
  `breadcrumb.rules` for the links, and does not copy them.
- Write `# bcr init, bcr VERSION` as the first line of the
  `.breadcrumbs` plain `bcr init` writes.
- State it all in `specs/init/spec.md`, add a test for each new
  Scenario, and tick its Definition of Done.
- Document the flag under `### init` in `docs/bcr.md`, and in its
  SYNOPSIS; generate `docs/bcr.1` again (ADR-0008, ADR-0009).

## Refinement Protocol
If the layout needs a file or a rule ADR-0027 does not name, stop and
ask. If a template needs wording the ASDLC pages do not give, keep it
to a line that says what the section holds.
