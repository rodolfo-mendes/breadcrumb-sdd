# PBI-00009: Read records in one package

## Directive

Add the package that reads the records `bcr extract` prints, and move
their printing into it, so that one package writes and reads the
format, as `specs/verify/spec.md` describes.

**Scope:**
- Add a package of its own for records, such as `internal/records`.
  It is infrastructure (ADR-0013).
- Move the printing of `breadcrumb` and `link` records from
  `cmd/bcr/extract.go` into it. `bcr extract`'s output does not change.
- Read records line by line:
  - a line may end in `\n` or `\r\n`;
  - `breadcrumb` needs at least five fields and `link` at least six;
    fields after those are ignored;
  - a record of another kind is skipped;
  - `LINE` is a whole number from 1;
  - any other line, an empty one included, is an error that gives its
    number in the input.
- Turn the records into the set of breadcrumbs `internal/crumb`
  checks (PBI-00008), each link with its own path and line.
- Test that what the package writes, it reads back the same.
- Leave `cmd/bcr` without `verify`: PBI-00010 adds it.

## Dependencies
- Blocked by: PBI-00006, PBI-00008
- Must merge before: PBI-00010

## Context
Read: `specs/verify/spec.md`
- Interface, for what is a record
- Scenarios "Records of a kind it does not know", "Fields added at the

Read: `specs/extract/spec.md`, Interface, for the fields.

## Verification
- [ ] `go test ./internal/records` passes, with a test for each rule in
      Scope.
- [ ] `go test ./cmd/bcr` passes, and `bcr extract`'s output is the
      same as before.
- [ ] `internal/crumb` does not import the new package.
- [ ] `go test ./...` passes.

## Refinement Protocol
If reading a record needs a field or a rule the specs do not state,
stop and ask: the records are the contract between the two commands.
