# TD-0025: A Task's claims follow the code

Parent: [IN-0004](IN-0004.md)

## Decision

When a change rewrites a line that a claim of an earlier Task quotes,
and what the earlier Task recorded still holds, the change updates
that claim in place. The change's own Task names each claim it
updated.

When what the earlier Task recorded no longer holds, its claim is left
as it is, Refuted: that is drift, and the change fixes the code or
records a new decision instead.

## Why

A claim quotes the code, and the code keeps changing. If an earlier
Task turned red every time a later change rewrote a line it quotes, a
Refuted verdict would mean "edited" as often as "broken", and readers
would learn to ignore it.

Git keeps each claim as it was, so updating one in place loses
nothing.

## What it beat

- Leaving earlier Tasks untouched, with the new Task carrying the
  claim forward: the earlier Task stays Refuted, or its claim has to
  be deleted, and the record of what it quoted moves away from it.
- Claims that avoid lines likely to change: a claim is strongest on
  the line that carries out the decision, and that line can change
  too.
