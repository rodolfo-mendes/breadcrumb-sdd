# IN-0002: The model is code

Write the model of Breadcrumb SDD, its breadcrumbs and the audit over
them, as code in this repository first, and derive the specification
from the working software afterwards. Build it incrementally, using
breadcrumbs to build it.

Motivation:

- Code is already the most detailed specification there is, and the
  only one precise enough to deterministically drive a computer.
  Programming languages are the best specification languages we have.
- Breadcrumb SDD holds that code is the source of truth. The method's
  own model should follow the same rule.
- A specification designed up front runs ahead of anything that can
  test it. Analysis piles up while the repository makes little
  progress.
- Tooling and its tests end up describing the format more precisely
  than the prose that was meant to define it.
- Iterating on software that runs produces evidence. A specification
  written after that evidence exists has something to be checked
  against.
- The path to the result should stay visible, back-and-forth
  included, not hidden behind a clean design made up front.
