# TD-0004: Record what the software must do as Requirements

## Decision

A Requirement states one thing the software built in this repository
must do, precisely enough that a reader can check the code against
it. Each lives in `breadcrumbs/` in a file named `RQ-NNNN.md`, where
`NNNN` is a four-digit number.

## Why

An Intake says what someone asked for, not what to build, and it
leaves gaps. A Requirement closes one gap at a time, so each can be
checked, and broken, on its own.

## What it beat

- Checking the code against the Intake directly: its gaps would be
  closed in each reader's head, differently each time.
- Several things in one Requirement: one broken part would hide
  whether the rest holds.
