# TD-0023: The man page is generated from the Markdown contract

Parent: [IN-0006](IN-0006.md)

## Decision

`docs/bcr.1` is generated from `docs/bcr.md` by the package
`internal/manpage`, which turns the part of Markdown TD-0022 allows
into roff. Both files are committed.

A test fails when `docs/bcr.1` differs from what `docs/bcr.md`
generates. `go test ./internal/manpage -update` writes it again.

The release workflow (TD-0017) packs `docs/bcr.1` into each archive
beside `LICENSE` and `README.md`.

## Why

Two contracts written by hand would drift apart. Generated, the man
page cannot say anything the Markdown does not, and the test catches
a Markdown change whose man page was not written again.

Committed, the man page can be read in a clone with `man ./docs/bcr.1`
and packed into a release without running the generator.

## What it beat

- A Markdown converter such as pandoc or go-md2man: a dependency
  (TD-0010), for the few elements TD-0022 allows.
- Generating the man page only in the release workflow: nothing in
  the repository would show it, and a broken conversion would show
  only at release.
- Writing the Markdown from the man page: roff is harder to write and
  to review than Markdown.
