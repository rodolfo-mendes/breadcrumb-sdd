# TD-0027: How bcr new is called and numbers breadcrumbs

Parent: [IN-0012](IN-0012.md)

## Decision

`bcr new` names the type by its prefix, `IN`, `RQ`, `TD` or `TK`, and
takes the parents as operands after the title, not as a repeated flag.

The next number is one more than the highest of the type. A number
left free by a breadcrumb that was deleted is not used again.

A breadcrumb made by `bcr new` is a draft like any other: an Intake or
a Requirement still needs a person's approval before it is committed
(TD-0006).

## Why

The prefix is what the file name and the id already use, and it has
no space in it to quote.

Flags come before operands (TD-0020), and a flag given twice keeps its
last value (`internal/cli`), so a repeated `--parent` would need a new
rule. Operands already name breadcrumbs, and let the parents come from
a pipe with `-`.

A deleted breadcrumb's number stays in git's history; used again, it
would name two different breadcrumbs.

## What it beat

- Type names such as `Technical Decision`: longer, and quoted in the
  shell.
- A repeated `-p PARENT` flag: it breaks a rule of the parser, for no
  gain over operands.
- Filling the lowest free number: the numbers would stop telling the
  order in which breadcrumbs were written.
