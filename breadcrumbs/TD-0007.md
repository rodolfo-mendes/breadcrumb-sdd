# TD-0007: The model is code; the specification comes later

Parent: [IN-0002](IN-0002.md)

## Decision

The model of Breadcrumb SDD, its breadcrumbs and the audit over them,
is written first as code in this repository. Until a specification
exists, that code is the definition of the method.

This repository writes no specification until a repository other
than this one adopts Breadcrumb SDD. The specification is then derived
from the working code.

## Why

IN-0002 gives the motivation for writing the model as code first.

A repository that adopts the method is the first reader that cannot
be expected to read this code. That is when a specification becomes
necessary, so that is when it is written.

## What it beat

- Writing the specification first: its rules are designed before
  anything runs that could test them.
- Writing the specification and the code together: two definitions of
  one method, drifting apart.
- Deriving the specification once the model covers IN-0001: it ties
  the method's rules to one use case.
- Leaving the end open: nothing would show that the specification is
  overdue.
