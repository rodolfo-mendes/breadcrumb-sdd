# TD-0037: The report is written by the release's own bcr

Parent: [IN-0018](IN-0018.md)

## Decision

`cmd/specsite` exports the repository at the latest tag with
`git archive` into a temporary directory, and runs, in it,
`go run ./cmd/bcr audit-report --html -o FILE`: the `bcr` of that
release, on the files of that release. An exit status of 1, which
means the report found something wrong (RQ-0010), still counts as a
report written.

## Why

IN-0018 asks for the breadcrumbs as they are at the latest release.
Their verdicts depend on the files their claims read, and on the rules
of the `bcr` that audits them; both are the release's own. The site
is built on the default branch (TD-0033), which may already hold
changes no release carries.

`git archive` writes only the files committed at the tag, which is
what a claim of that release could read.

## What it beat

- Auditing with the model of the default branch, inside `specsite`:
  the report could show rules, or code, that no release has yet.
- Downloading the release's binary: one more download, for a build
  that already has Go and the code of every tag.
- A checkout of the tag with `git worktree`: it leaves state in the
  clone to clean up, for files `git archive` gives as well.
