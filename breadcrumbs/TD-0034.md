# TD-0034: What bcr init writes, and how it finds what is there

Parent: [IN-0017](IN-0017.md)

## Decision

The first breadcrumb `bcr init` writes is a Technical Decision to
adopt the method, as TD-0001 is in this repository. It is written
only into a `breadcrumbs/` with no breadcrumb.

`bcr init` knows each piece is set up by a name: the file of the
workflow, and the `## Breadcrumb SDD` heading in the agents file
(RQ-0046). It
does not compare what is there with what it would write.

The section of the agents file and the workflow are fixed text, filled in
with the version of the specification and of `bcr`.

## Why

git keeps no empty directory, so `breadcrumbs/` needs a file to be
committed. A breadcrumb is the only file there that `bcr check` does
not warn of (RQ-0023), and the decision to adopt the method is the
first one a repository makes.

Found by name, a piece a team has edited still counts as set up, and
is never written over.

## What it beat

- An empty `breadcrumbs/` with a `.gitkeep`: `bcr check` would warn
  of it, and it records nothing.
- Markers such as HTML comments around the section of the agents
  file,
  so that `bcr init` could rewrite it for a new version: rewriting is
  what IN-0017 asks it never to do.
- A template the user can change: nothing asks for one yet.
