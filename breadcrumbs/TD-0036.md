# TD-0036: bcr knows its version

Parent: [IN-0017](IN-0017.md)

## Decision

`bcr` knows the version it was released as. The release workflow
sets it at build time, with
`-ldflags "-X main.version=VERSION"`. A `bcr` built by
`go install ...@vVERSION` takes it from the build information Go
records. Any other build has no version.

`bcr init` needs the version to pin the check (TD-0035). A `bcr` with
no version refuses to run `bcr init`, and writes nothing.

## Why

Until now nothing in `bcr` needed its own version. The check it sets
up must install the same release, so it needs one it can trust.

## What it beat

- Pinning the check to the latest release: the check could move to a
  new version of the specification the repository never adopted.
- A version written in the source and raised by hand: one more step
  in every release, and wrong when it is missed.
- A `--version` flag: nothing asks for it yet, and the contract would
  grow a flag no command needs.
