# TD-0029: bcr embeds the specification from docs/

Parent: [IN-0015](IN-0015.md)

## Decision

The specification stays in `docs/breadcrumb-sdd.md`. A Go package
beside it, `docs`, in `docs/docs.go`, embeds it with `//go:embed` and
exposes it as `docs.Spec`. `bcr spec` writes `docs.Spec`.

## Why

`//go:embed` can only embed files in its package's directory or
below, so the package has to sit in `docs/` or the file has to move.
Readers and the contract already find the documents in `docs/`, and
the contract's links to the specification stay as they are.

Embedded at build time, the specification cannot differ from the one
in the commit the binary was built from, and `go install` carries it
with no step of its own.

## What it beat

- Moving the specification into an `internal/` package: it would hide
  the document readers need most among the code.
- Copying it into `cmd/bcr` with `go generate`: two copies, one of
  them drifting when the step is forgotten, and `go install` would
  build whatever copy was committed.
- Reading the file at run time: it would need the repository of
  Breadcrumb SDD, which an adopter does not have.
