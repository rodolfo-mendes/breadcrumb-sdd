# IN-0004: Tasks

Record each change to this repository as a Task: a breadcrumb that
states, as claims `bcr` can check against the files, what the change
left in the repository. A Task names the Technical Decisions and
Requirements it carries out as its parents.

A Task is Confirmed when all its claims hold, and Refuted when any of
them fails or cannot be read. A breadcrumb above it is Confirmed only
when every breadcrumb below it is Confirmed.

Keep it minimal: Tasks are named `TK-NNNN.md`, like the other
breadcrumbs, and start with a single kind of claim, that a file
contains a piece of text.

Motivation:

- The audit report draws every breadcrumb gray. Nothing in the
  repository can be Confirmed or Refuted until something states what
  the code should hold.
- The repository now has code. Checking by eye that it still matches
  its breadcrumbs stops being quick as the code grows.
- Without Tasks, the chain from an Intake down to the code breaks at
  its last link.
