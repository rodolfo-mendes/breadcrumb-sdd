# TD-0031: Build the whole site from the tags

Parent: [IN-0016](IN-0016.md)

## Decision

The site is a function of the `v` tags. Each build reads
`docs/breadcrumb-sdd.md` at every tag, keeps the latest tag for each
version of the specification, and writes every page again, with
`spec/latest/` and the root. Nothing from an earlier build is kept.

A program in `cmd/specsite` builds the site into a directory, reading
the tags with `git`. It is not part of the toolkit, and no release
carries it.

## Why

GitHub Pages deployed from a workflow replaces the whole site each
time. Rebuilt from the tags, every version's page is there on each
build, and a page can always be built again from the history.

Taking the latest tag of a version lets a change of wording, which
keeps the version (TD-0030), reach its page.

## What it beat

- A `gh-pages` branch that each release adds a page to: the site
  would be state kept apart from the history, and a page lost or
  broken there could not be built again.
- Publishing only the spec of the tag being released: every earlier
  version would disappear from the site.
- The earliest tag of a version: fixes of wording would never be
  published.
