# TD-0020: Command-line conventions of bcr

Parent: [IN-0007](IN-0007.md)

## Decision

A `bcr` command is run as `bcr COMMAND [FLAGS] [OPERANDS]`. Flags
come before operands; the first operand ends the flags.

On standard output, a result is one record per line, with its fields
separated by a tab. There is no header line and no color.

On standard error, a message starts with `bcr: `. A usage error is
followed by the command's usage line.

A problem found in a file is written `PATH:LINE: MESSAGE`, with the
path relative to the repository root.

## Why

Tab-separated lines can be read by `cut`, `awk`, `grep` and `sort`
without a parser. `PATH:LINE: MESSAGE` is the form compilers and
`grep -n` use, which editors already know how to jump to.

Flags before operands is the POSIX utility syntax, and it makes an
operand that starts with `-` unambiguous.

## What it beat

- JSON output: exact, but it needs `jq` to go down a pipe, which POSIX
  does not have.
- Aligned columns: readable by eye, but a title with spaces cannot be
  cut out of them.
- Flags anywhere among the operands, as GNU tools allow: convenient,
  but not POSIX, and an operand could be read as a flag.
