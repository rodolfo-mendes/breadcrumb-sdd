# IN-0001: The Audit Diagram Use Case

Imagine we have a mature repository of a service running in production. The repository is building, the service is deployed,
and so far, only minor bugs stand on the Agile board. Typical day of a service in production. 

This repository has a mature, running installation of Breadcrumbs, with Tasks, Decision Records, Requirements and Intakes.

A developer of the team, in a typical day of work, wants to merge his feature branch into main. Before opening the PR,
this developer merges his feature branch into the main branch locally, without pushing it. With the main branch checked out,
he opens a terminal, cds to the root of the repository and types a command:

```
$ bcr audit-report --html
```

This command, which is part of the toolkit, runs an automated audit across the breadcrumbs and generates a report in HTML format.
The developer opens this report, and what it looks like: it is a graph. It looks like a class diagram: each node is a rectangle with
arrows coming in and going out to other nodes. Each rectangle shows the properties of that breadcrumb. The arrows show how
breadcrumbs are related to each other. And one of the most important pieces of information: the color! Green nodes are Confirmed.
Red nodes are Refuted. Gray nodes are Undecided. Thus, one can track the whole chain and where it breaks: if a given Task is refuted,
that task does not hold the Technical Decision and in turn breaks a requirement.
